Problem

Existing B2B protocols move documents well. They do not describe agent-native procurement well.

EDI, AS2, SFTP, FTPS, and partner-specific APIs remain critical to enterprise procurement. But most of them standardize transport, mapping, and document exchange rather than structured, discoverable workflow semantics for AI systems.

That leaves developers rebuilding procurement logic across ERP adapters, supplier portals, marketplaces, and custom integrations. UPP focuses on the workflow layer: what a vendor supports, how a quote is requested, how an order is approved, and how an invoice is matched.

What Is UPP?

A small-core protocol for AI-native procurement interoperability.

Developer-first

JSON Schema first, OpenAPI-compatible, versioned, and built to be implemented rather than debated.

Enterprise-safe

Designed for explicit approvals, bounded automation, and compatibility with existing ERP and procurement systems.

Extensible

Small interoperable core with namespaced vendor extensions for category or partner-specific behavior.

Developer Architecture

Machine-readable by default.

UPP is designed to be expressed as JSON Schemas, served through predictable APIs, and mapped into ERP, procurement, and integration platforms. Capability discovery is explicit. Extensions are named. Transport can vary, but the workflow contract remains stable.

The protocol is informed by patterns from MCP and modern API ecosystems, but avoids unsafe tool execution models. Procurement actions should be validated, permissioned, and auditable.

Vendor Extensions

Standard where it counts, flexible where it has to be.

UPP supports namespaced extensions such as com.b2bprotocol.procurement.rfq and com.vendorname.custom_pricing. Unknown optional extensions should not break baseline interoperability.

Roadmap

Build the protocol in public, starting with a minimal viable surface.

Phase 1

Draft spec, schemas, OpenAPI, examples, and the initial website.

Phase 2

Reference server, validation tooling, status events, and ERP mapping guidance.

Phase 3

Conformance tests, partner onboarding workflows, and an extension registry.
